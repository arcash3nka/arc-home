# arc-fm.web

Сайт-визитка, сделанный как браузерный порт моего файлового менеджера на C++.
Две панели, path bar, status bar, навигация с клавиатуры, рабочая командная
строка и процедурный бонсай, который вырастает из содержимого сайта.

Ноль зависимостей, ноль сборки: обычные ES-модули. Файлы кладутся на хостинг
как есть.

---

## Запуск

Модули требуют http, с `file://` не заработает:

```bash
python3 -m http.server 5199 --bind 127.0.0.1
```

Дальше <http://127.0.0.1:5199>.

**Двойной клик по `index.html` не сработает.** Safari и Chrome запрещают
страницам грузить ES-модули по схеме `file://` — это правило безопасности
браузера, а не поломка сайта. Раньше в этом случае экран загрузки просто
застывал; теперь через две секунды появляется объяснение и команда выше.
На GitHub Pages ничего этого не нужно: там обычный `https://`.

## Публикация на GitHub Pages

1. Создать репозиторий `arcash3nka.github.io` и залить туда содержимое папки.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/`.
3. Всё. Сборки нет, деплой — это `git push`.

Файл `.nojekyll` уже лежит рядом: без него GitHub Pages игнорирует
директории, начинающиеся с подчёркивания, и однажды это выстрелит.

## Где что править

Трогать нужно только `data/`. Всё остальное — движок.

| Файл | Что внутри |
|---|---|
| `data/profile.js` | Имя, статус, текст «о себе», факты под именем |
| `data/stack.js` | **Карточки технологий.** Один объект = одна карточка = одна гроздь листьев на бонсае |
| `data/projects.js` | Проекты. `repo: null` → карточка честно пишет «ещё не опубликовано» |
| `data/education.js` | Линия времени и контакты |
| `data/dotfiles.js` | **Скрытый раздел под `^H`** — псевдо-конфиг, `.plan`, `KNOWN_BUGS`. Здесь можно материться и шутить, на обычных страницах — нет |
| `data/tree.js` | Список разделов (левая панель) |
| `data/ui.js` | Подписи интерфейса, экран загрузки |

Каждая строка двуязычная: `{ en: '…', ru: '…' }`. Английский — основной,
русский подхватывается сам, если у посетителя русский браузер.

### Добавить технологию

Один объект в нужную группу `data/stack.js`:

```js
{
	id: 'rust',
	name: 'Rust',
	level: 2,                                   // 0..5, честно
	since: { en: 'learning', ru: 'изучаю' },
	accent: 'peach',                            // цвет из палитры
	note: { en: '…', ru: '…' },
}
```

Появится карточка, и на дереве станет на гроздь больше. Больше ничего.

### Добавить раздел

1. Объект в `data/tree.js` — `id`, `block`, `glyph`, `accent`, `desc`.
2. Файл в `src/blocks/`, экспортирующий функцию, которая возвращает DOM-узел.
3. Строчка в `src/blocks/registry.js`.

Вёрстку править не нужно ни в одном из случаев.

Необязательный ключ `rail: false` в объекте раздела убирает правый рельс с
бонсаем и отдаёт его ширину содержимому. Сейчас им никто не пользуется, но
он рабочий.

## Как всё устроено

```
index.html            каркас окна: панели, полосы, оверлеи
styles/
	theme.css           палитра Catppuccin (mocha + latte), сброс, CRT
	layout.css          раскладка панелей и адаптив
	components.css      карточки, шелл, тепловая карта, бонсай
src/
	main.js             композиция: курсор, навигация, оверлеи
	core/               состояние, роутер, i18n, шелл, GitHub API, DOM-хелпер
	ascii/              бонсай и горящая сфера + их отрисовка
	blocks/             по файлу на раздел
data/                 контент
```

### Бонсай

`src/ascii/bonsai.js` — не картинка, а рекурсивное ветвление с
детерминированным seed от календарного дня: одно и то же дерево весь день,
новое завтра. Каждая гроздь листьев получает тег навыка или проекта, поэтому
карточка умеет подсветить свою часть кроны.

Проверить дерево, ничего не открывая:

```bash
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc -m test-bonsai.mjs
```

### Сфера

`src/ascii/avatar.js` — горящий шар на `00_whoami`. Не картинка и не спрайт:
каждый кадр считается из геометрии сферы и двух полей шума.

Форму держит **потемнение к краю диска**, как у настоящей звезды: луч
зрения у края идёт по касательной сквозь более холодные слои. Это
неочевидно, но принципиально — один лямберт даёт освещённый мячик, а один
шум даёт бесформенное пятно, в котором шара не видно вовсе.

Вокруг — корона. Шум для неё берётся **по углу**, поэтому языки обтекают
шар по окружности, а не торчат иглами наружу; вверх они тянутся дальше,
чем вниз, потому что жар поднимается. Порог вычитается прямо из шума:
там, где он не дотянул, пламени нет совсем — иначе вокруг шара висит
ровная дымка вместо отдельных языков.

Цвет — шкала жара: белое ядро, кремовое, оранжевое, красное, пурпурное,
синее к холодному краю. Самое горячее ядро цвет получает от темы (класс
`av-core`): на светлом фоне белое просто исчезло бы.

Анимируется 12 кадрами в секунду и только пока вкладка видна.

### Шелл

`:` открывает командную строку. Команды `ls`, `cd`, `cat`, `open`, `grep`,
`tree` работают по тем же данным, что и карточки, и реально двигают страницу.
`help` покажет список; часть команд в нём не указана.

### Масштаб интерфейса

Все размеры заданы в пикселях, и на мониторе шире двух тысяч точек это
выглядит мелко. Вместо перевода сотни значений в `em` окно масштабируется
целиком: переменная `--ui` в `theme.css` и `zoom` на `.app`. Высота и поля
окна там же делятся обратно на `--ui` — `zoom` масштабирует и содержимое,
и собственные размеры элемента, иначе окно вылезает за экран.
